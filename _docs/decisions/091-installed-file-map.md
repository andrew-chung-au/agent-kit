# Decision: Installed-file map and joint import and feedback workflow (#91)

Status: APPROVED by the human on 2026-11-03: items 1 to 8 as written, no changes, and option 3 for the two `vuln-triage/` copies (Orchestrator comment https://github.com/andrew-chung-au/agent-kit/issues/91#issuecomment-6613018258).

Why a record and not a body section: the PM was told not to edit the issue body, so the record is filed as this file and posted in a PM comment on #91. The orchestrator's hash check covers the comment text; the Engineer then commits it as a file (suggested path `_docs/decisions/091-installed-file-map.md`; the kit fixes no folder) and adds its row to `_docs/index.md`.

- **Decision:**
  1. One plain-text map file inside the kit folder, `agent-kit/installed-files.txt` (the human chose location "new file in the kit folder" on 2026-11-03). One line per entry: `<path inside the kit> | <install path> | <kind> | <allowed-to-differ>`. Comment lines start with `#`. Read as text only, never sourced.
  2. Two kinds. `repo`: installed inside the repo (`.devcontainer/devcontainer.json`, `.devcontainer/setup.sh`, `.github/workflows/verify.yml` from `templates/ci-verify.yml.template`). `human-machine`: installed on the human's machine (`~/.agent-hooks/pre-push` and each clean clone's `.git/hooks/pre-push`, from `environments/local-sandbox/pre-push`). Installer is the human only for both kinds (agents never edit them). Sandbox tools never open a `human-machine` entry's install path; those are compared only by the human, from the clean clone, with git only (never `make`, never running a repo file).
  3. One shared parser/scan function (in `agent-kit/scripts/`) that `kit-check`, `kit-compare`, the forward import and the reverse import all call, so they cannot disagree. It rejects any `repo` entry whose install path is absolute, contains `..`, starts with `~`, is outside the repo, or resolves through a symlink (the path or any parent). A rejected entry fails the whole read loudly; a reader never skips it silently.
  4. Allowed-to-differ lines: a marker pair in the installed file (`agent-kit: local-begin` / `agent-kit: local-end` in a comment) wraps personal lines such as a name or noreply email. Lines between markers are ignored by comparison and reported as "local, ignored"; any difference outside them is reported as drift. Where a file cannot hold comments, the map's fourth field holds a literal line prefix instead. A missing marker pair on a file that needs one is drift, not a pass.
  5. Tool use, all read-only: `kit-check` reads the map and the installed copies in the repo and reports drift against the kit copy. `kit-compare` does the same against another kit copy or a pristine release. Forward import adds an "installed files" step to its report (copy is by the human, from a clean clone). Reverse import reads installed copies and writes a feedback bundle (changed installed files plus changed kit files, with the local-marker lines stripped) under `.scratch/`, replacing the hand-made bundle of #89. No tool writes an installed file.
  6. Release zip (#9): the map ships inside the kit folder so it travels in the zip and is covered by the manifest. The zip still unpacks only the kit folder; the release procedure states that installed files are not in the unpack location and are placed by the human using the map.
  7. Tier: Heavy (shared scripts that run live, a new shared format, a trust rule). Build is split into issues (proposed, not filed): (a) map file plus shared parser and refusal tests; (b) `kit-check` and `kit-compare` read the map (absorbs the recipe-drift part of #7); (c) forward-import step, in the import procedure after #77 lands as written; (d) reverse import with feedback bundle; (e) human-only read-only comparison for the push check from the clean clone, documented in `environments.md`; (f) release note for #9.
  8. Two kit copies under `vuln-triage/` (`vuln-triage/agent-kit/` and `vuln-triage/_docs/agent-kit/`): stay for now, as the human said on 2026-11-03. They are settled by this record's follow-up, see the open question below. Until then no tool treats either as authoritative, and the map and parser take one explicit kit root so they can be pointed at either.

- **Reason:** The map is kit data, not project settings, so `agent-kit.conf` (per-project, editable by the project) is the wrong home and could let a project narrow what is checked. The manifest should stay a plain hash list. A file in the kit folder is covered by the manifest and the zip, and leaves existing formats alone. One shared parser removes the risk of the readers disagreeing. Marker lines keep personal values in the installed file where the human edits them, and make a check able to tell personal from drift. Splitting `repo` from `human-machine` honours the rule that the push check lives outside this folder and cannot be read by a sandbox tool.

- **Alternatives:** (a) Map in `agent-kit.conf`: reuses a file already read, but is per project, protected, and mixes kit facts with personal values. (b) Extend `MANIFEST.sha256`: already records pristine content, but it is generated by a release step, holds only in-folder hashes, cannot hold allowed-differ lines and changes a format `kit-check` and `kit-manifest` depend on. (c) Allowed-differ by line range instead of markers: breaks as soon as the file is edited. (d) Allowed-differ only by map patterns: safer against a project removing markers, but personal values then live in the kit-side map instead of beside the line. (e) Do nothing: drift stays unseen (#4, #5) and feedback stays hand-made.

- **Trade-offs:** A new file, a new format and a parser every reader depends on (a bug there affects all of `kit-check`, `kit-compare` and import; mitigated by tests, including the refusal cases). The build edits `agent-kit/scripts/`, which runs live and changes `make verify` and the guards for the very change being built. The `human-machine` push check is only compared when the human runs the git-only comparison, so a sandbox check cannot prove it is current. Markers can be deleted by a project; the check treats missing markers as drift. Not urgent: waits on #88 (PR #97 merged, QA check in progress) and on #73; if QA on #88 fails, step (a)'s scan sharing waits for the fix.

## Open question for the human: the two kit copies under `vuln-triage/`

`vuln-triage/agent-kit/` and `vuln-triage/_docs/agent-kit/` both hold a full kit tree (same top-level folders). The PM has not diffed them or checked which one the project's docs and scripts point at. Options:
1. Keep `vuln-triage/_docs/agent-kit/` (the path the kit docs name as `_docs/agent-kit/<path>`) as the single installed kit, and the human removes `vuln-triage/agent-kit/` after the reverse import has captured anything the project changed there. Recommended, if the project's AGENTS.md and Makefile point at `_docs/agent-kit/`.
2. Keep `vuln-triage/agent-kit/` (the same layout as this repo) and remove `_docs/agent-kit/`. Better only if the project's references already use that path.
3. Keep both until the reverse import and feedback bundle exist (build step d), then decide with a real comparison. Safest, and matches "stay for now".
Recommendation: option 3 now, then option 1 or 2 by what the comparison shows. Removing a copy is destructive and files the project owns, so the human does it; no agent deletes either copy. The verification step: a read-only comparison of each copy against the pristine kit and against each other, run by an agent into `.scratch/`, before the human chooses.

Chosen by the human on 2026-11-03: option 3.
