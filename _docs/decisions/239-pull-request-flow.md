- **Decision:** Opening a draft pull request from the session's own pushed branch, and readying it when the C5 conditions hold, are mechanical steps that are never asked or logged. Opening goes only through `make pr-open`, which refuses close keywords, a missing `Refs` line, secrets, the default branch and an unpushed branch. Readying uses the tool's pull-request feature where one exists. Merges, labels, waivers, closing and pushes to `main` stay `gate` stops. Projects without an agent push opt-in keep today's flow, with the human pushing.
- **Reason:** The human's view in session (2026-11-23) and the #200 trial ruling. The PR asks in #204 (#240, #241) were avoidable stops. A draft cannot be merged by mistake, and `main` changes only at the human's merge, so opening and readying change nothing the human hasn't reviewed.
- **Alternatives:** Keep asking before each pull request (an avoidable stop per issue). Open through the tool's connector with no target (no secret scan and no tested refusals; a raw `gh api` call prompts in this repo). Open a ready, non-draft pull request at the first push (CI alongside QA, but nothing signals "not yet").
- **Trade-offs:** A new script and target to maintain (Effort R). Readying depends on the tool: outside a Claude Code cloud session the draft stays a draft for the human to ready. The C5 conditions are checked by the orchestrator's reading, not a script.
- **Evidence:** #200 Ruling comments (2026-11-22); the #204 session summary `_session-summaries/2026-11-23T2043Z-issue-204-orchestrator-decision-points.md`; PRs #240 and #241; PR #243 (#206), opened as a draft at the first push and readied after both QA launches passed, by hand before this issue; `process.md` Decision points and Commits and pushes at `272479e`, unchanged at `3faa409`.

Design note from the body: the open and ready steps are mechanical because merging, the step that changes `main`, stays a `gate`. Opening goes through a `make` target because every GitHub write in the kit goes through one that scans for secrets and checks its inputs (`AGENTS.md`, Command shape). The target is also pre-approved, which removes the permission prompt a raw `gh api` call raises.
