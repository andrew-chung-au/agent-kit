# Decision: every role writes a reflection file at the end of each launch, the orchestrator appends it to one append-only file per issue, and the sweep reads those files

The human approved this record with the groomed body (2026-11-23 grooming, D-206-1 answered by the human in session with every recommendation, q1=A, q2=A, q3=A; `approved` label covering body sha256 `aeb3b2e6f9f1c2f3a189a2ca1b43d86ab832f0025862ca88dea4b497935d1971`, Orchestrator Claim comment on #206, 2026-11-23). Copied here from the issue body's `## Decision record`.

- **Decision:** Every PM, Engineer and QA launch ends by writing `.scratch/reflection-<issue>-<role>.md` from `templates/reflection.md`. The orchestrator appends it unchanged to the append-only `_docs/records/reflections/<issue>.md` and commits it before the next launch. The sweep reads those files, plus the Reflection blocks of summaries written before the change. The post-PASS reflection launch is removed.
- **Reason:** On #204 the separate launch was skipped after three usage-limit stops, so no role's reflection was kept. A reflection written inside a launch the role is already running costs a few lines, not a launch. A file per issue matches the findings log (`<issue>.json`) and the decision ledger (`<issue>.jsonl`), and survives #207 retiring the summary.
- **Alternatives:** Keep the post-PASS launch and write the file from it: the same cost that failed on #204. Add a `Reflection:` field to the role return: it changes the ten-line format, `check-format.py` and every role's return. One file per role (`<issue>-<role>.md`, as first filed): a role launched several times would need edits or numbered files. Roles commit their own files: QA cannot change the tree, and the PM writes no repository files.
- **Trade-offs:** One small orchestrator commit per launch, and more sections per issue (one per launch, many of them `Nothing to report.`). A reflection from a launch that stops early is lost. The append-only rule is enforced by reading, not a script.
- **Evidence:** `_session-summaries/2026-11-23T2043Z-issue-204-orchestrator-decision-points.md` (Reflection); `agent-kit/procedures/sweep.md` step 2 and `agent-kit/procedures/session-summary.md` at `272479e`; `_docs/planning/kit-1.11/workflow-review.md` sections 3.8 and 12.

Design note from the body: the reflection travels in a fixed `.scratch/` file that the role writes before its return, and the orchestrator copies it into the repository. It doesn't travel in a separate launch or a new return field. QA may not change the tree, and the PM writes no repository files, so only the orchestrator can commit a record. The return format stays as #198 fixed it.
