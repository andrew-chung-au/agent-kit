# Decision: line-based report formats checked by check-format.py

Issue #198 (Heavy). The human approved this record with the groomed body (2026-11-21 grooming, three questions answered with option 1; `approved` label covering body sha256 `16296c05579faf1fb73e6b7ed65eb03c8633f2fe8ba09be13d86c8381013e085`, Orchestrator Claim comment on #198, 2026-11-22). Copied here from the issue body's `## Decision record`.

- **Decision:** The role return, finding, QA comment and message to the human are line-based, one `<Label>: <value>` field per line from column 1 (the #197 rule). Finding labels map one to one to the findings-log JSON keys. The QA comment's first line stays `QA: PASS` / `QA: FAIL`. `agent-kit/scripts/check-format.py` (standard library, one table of formats, reusing `settings.py`'s `clip`, `echo`, `lines_of` and refusal form) checks shape, not truth, through `make check-format`.
- **Reason:** #199, #200, #204 and #214 read these fields, so the fields must be exact and one grammar across settings and reports keeps one reader style. The evidence is in Why: renumbered QA ids, long returns, impact grades the human had to ask for.
- **Alternatives:** (1) The proposal's dense lines (`F-12-1  impact: C  effort: R ...`, several fields per line): shorter, but a second grammar beside #197's, and near-misses are harder to refuse. (2) JSON in comments: exact, but humans can't read it at a glance. (3) pydantic or a JSON-schema library: a dependency the kit's rule forbids without a decision (proposal 5, "Why not pydantic"). (4) Prose with a few anchors: today's cost stays.
- **Trade-offs:** A finding takes eleven lines instead of four, so QA comments grow per finding. A role return is always exactly ten lines. A format change needs `check-format.py`, the doc example and the tests changed together. A comment that passes can still be wrong, so the check catches slips, not a role set on misreporting (all roles share the owner's account).
- **Evidence:** #197's two QA comments and `_docs/records/findings/197.json` (`provisional` note); `_docs/planning/kit-1.11/workflow-review.md` sections 1, 2.3, 5 and 8; `agent-kit/procedures/orchestrator-comments.md` ("Lines scripts read"); `agent-kit/scripts/issue-close.sh` (first-line verdict).
