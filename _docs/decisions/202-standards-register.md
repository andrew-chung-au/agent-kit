# Decision: standards are short files in one register, named on a column-1 `Standards:` line and checked by QA through a named `make` target or a reading

Issue #202 (Heavy). The human approved this record with the groomed body (2026-11-23 grooming, D-202-1 and D-202-2 answered with option 1; `approved` label covering body sha256 `032890aad19a3cf479f9ad3ac141d5db7330d2e16e0e03ebb72799df80d75d2b`, Orchestrator Claim comment on #202, 2026-11-23). Copied here from the issue body's `## Decision record`.

- **Decision:** Standards live as short files in `_docs/standards/`, from `templates/standard.md`. An issue names the ones that apply on a column-1 `Standards:` line in Constraints (`none` when no standard applies), read by people and QA, with no script (D-202-1, option 1). A standard's check names a `make` target the project provides, or `read <file>` for a rule that isn't mechanical, and QA and the Engineer run it; the kit adds no runner (D-202-2, option 1). A breach of a listed standard is `Category: standard`, `Scope: in`; a breach of an unlisted one is `Scope: out`.
- **Reason:** Under `QA_SCOPE_STRICT=yes` only what the issue lists can fail, so the list has to be somewhere QA can find it and a standard has to say how it is checked. A body line follows the kit's existing pattern (`Overrides:`), and a `make` target follows its rule that project commands run through `make`, so it works for any project's test setup without the kit knowing the stack.
- **Alternatives:** (1) A `make standards N=<n>` target that reads the issue dump, checks each named file exists and prints its check: mechanical, but a new live script and effort E for a gap QA already sees. (2) A free-text bullet in Constraints: no format to check. (3) Standards described in prose with no named check: QA decides how to check, so two launches can disagree. (4) Putting the standards in `AGENTS.md`: always loaded, against the smaller always-loaded layer.
- **Trade-offs:** Nothing refuses a misspelt file name on the line; QA finds out when it can't open the standard. A standard whose check names a target the project hasn't written is read by hand until the target exists. An approved issue gains a standard only through a Confirm round trip, which costs a human message but keeps the approved text meaning one thing.
- **Evidence:** the grooming comments on #202 (the human's answers of 2026-11-23: option 1 of D-202-1 and D-202-2, and "ok" to the C4 rewording); `procedures/formats.md` (Scope) and `team/qa-engineer.md` (re-checks), which already refer to "the standards the issue lists"; `_docs/planning/kit-1.11/workflow-review.md` sections 3.4 and 9; socboard's QA failing work on step formatting, a rule its issues never named.
