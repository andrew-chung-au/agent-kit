# Decision: The on-call drill runs in one workflow of four jobs on an ephemeral stack, and `main` never holds the defect

One file per choice that may be revisited. **Status: approved** (the maintainer approved the Decision record of issue #299 by name; recorded in https://github.com/andrew-chung-au/socboard/issues/299#issuecomment-6939317286) (issue #299, O14; copied from the issue's `## Decision record` section; the defect was chosen at the decision point, see Evidence).

- **Decision:** the drill runs in one workflow of four jobs on an ephemeral stack: the drill job builds the incident bundle, the agent job makes a patch, the publish job checks it with `main`'s guard and opens a draft pull request against a throwaway `drill/<run id>` branch, and an unprivileged job proves the agent's test fails before and passes after. `main` never holds the defect.
- **Reason:** a committed defect in `main` would ship; a patch applied at run time keeps `main` clean and makes the run reproducible. Separate jobs keep the model key away from write access (#298). One run shows every step in order, which is the only evidence a reviewer can open once the dev server is gone.
- **Alternatives:** a feature flag in the app that injects the delay (adds a production code path and an attack surface); a separate repository (the evidence would sit away from the project); running against dev (puts a defect on a public server and needs a server big enough for the stack).
- **Trade-offs:** a run costs about 10 to 12 minutes of CI and a model key's spend; the agent investigates from a fixed bundle, not live queries; the agent's pull request targets a throwaway branch, so it shows the fix but is not merged into `main` as is; the drift check adds a `make test` run to the observability job.
