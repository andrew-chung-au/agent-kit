# Decision: Prod is promoted by a manual workflow that refuses before it asks for an approval, deploys a digest dev ran, and records who approved it

One file per choice that may be revisited. **Status: proposed** (Heavy tier: the one CD path to prod, using the CI deploy role; only the human sets `approved`). Issue #269 (body hash `0877a2615a879096fc9198b8d474ed26d81510b860844494a1d5b3ec3f491fb5`), copied from its `## Decision record` section with the two decision questions answered by the recommended options (the human has not chosen; the decision point asks). The GitHub and AWS details are unchecked until the first promote (`VERIFY:` comments in `scripts/ci_promote.py` and `scripts/ci_deploy.py`).

- **Decision:** (1) `promote-prod.yml` is started only by `workflow_dispatch`. A `resolve` job with no role and no Environment comes before the `promote` job in `deploy-prod`, so a refused digest never asks for an approval. (2) The digest is dev's newest `deploy-record-dev`, or an earlier digest held by a non-expired dev record (the newest 30); tag, revision and image come from the record, never from the input. A newest record that fails its check is refused, not replaced by an older one. (3) Rollback is a promote of an earlier digest through the same workflow. (4) The post-deploy check is the public health check of the prod URL, as dev's (decision question 1, option A). (5) The summary and a `deploy-record-prod` artifact record the digest, the previous prod digest, when, who started it and who approved it, read from GitHub's approvals endpoint (decision question 2, option A); a failure to read the approvers is recorded as `unreadable` and does not fail a deploy that already happened. (6) The logic is `scripts/ci_promote.py`, which reuses `ci_deploy.py`'s patterns and AWS calls; `ci_deploy.send` takes an `environment` argument defaulting to `dev`, and the dev call is unchanged.
- **Reason:** A refusal should cost nobody an approval. Reading only dev's records means prod gets only what dev ran. One workflow for forward and back is one path to approve and test. The record carries the approver because the deploy role cannot tell dev from prod (#268, trade-off 1); the gate and its evidence are GitHub's. Falling back to an older record when the newest is broken would promote something other than what dev runs now, so it is refused.
- **Alternatives:** the digest from the registry by tag (trusts a tag's target, needs a registry call); a second rollback workflow (two paths); one job that resolves and deploys (an approval for a run that would be refused); the Deployments API for the record (a new permission); the full five-step smoke with prod's lead password and ingest key as `deploy-prod` secrets (a credential in GitHub, a synthetic case in prod each run); the smoke run on the server by a second document (a new document, a role grant, a Terraform change); signed records.
- **Trade-offs:** (a) The workflow's file on `main` decides what runs, so anyone who can change `main` can change the gate; the Environment's reviewer is the control, and it applies only to jobs that name `deploy-prod`. (b) Records expire after 90 days; with none, promote refuses until dev deploys again. (c) A rollback is limited to digests in dev's newest 30 non-expired records. (d) The health check proves the proxy, the certificate and the app, not the database. (e) The approver's login depends on the approvals endpoint (`VERIFY:`). (f) With one reviewer who also starts the run, "prevent self-review" is off, so the approval is a deliberate click, not a second person. (g) Dev and prod share one lock on the server (#267), so a promote during a dev deploy fails with the lock's fixed line and is run again by hand. (h) An artifact's content is not signed. Only records uploaded by a run on `main` of this repository are read (the artifact list's `workflow_run.head_branch` and `head_repository_id`, `VERIFY:`), so a run on another branch or a fork's `main` cannot plant one; a workflow on `main` that uploads an artifact with the same name could, and the Environment's reviewer is the control for that.
